# 已有用户节点组授权调整验证

日期：2026-11-16。范围：本地 Go 主控/API/CLI、React 页面及独立 OpenAPI 契约；未部署或连接真实节点。现有工作区其它修改保留。

## 交付行为

- 管理员先选择组并预览新增、保留、撤销节点，再确认提交；预览只读，不生成凭据或任务。
- 按组并集计算权限。保留节点沿用凭据及相同配置回执；新增节点获得独立凭据；撤销持久记录指纹，再次加入使用新代凭据。
- 提交校验用户版本及预览摘要；摘要绑定当前凭据、节点组结果、目标配置与未完成撤销范围。重复请求沿用原操作，禁用可以覆盖未完成授权调整。
- 撤销目标优先于新增目标；订阅更新独立推进，失败不撤销已保存的节点任务。无就绪节点时撤下旧索引，有就绪节点时只发布仍授权且已验证的内容，保留原订阅令牌。
- API、CLI、网页均接入同一领域逻辑。页面只保存待确认请求 key、操作类型与用户 ID，刷新或丢响应后找回原任务。

## 最小必要验证

- `make check`：go vet 和全量竞争检测通过。新增 7 个 Go 顶层测试及 10 个校验子场景，覆盖重叠组、凭据保留、撤销优先、受阻后的重新授权、新代凭据、预览漂移、并发幂等、禁用抢占、订阅写失败恢复和 CLI。其中最后补充的“已标记撤销但节点尚未确认，再次调整仍跟踪该节点”用例单独通过竞争检测；未重复全量测试。
- Go HTTP 契约流程：实际预览/提交响应通过独立 OpenAPI 校验；验证预览不写库、CSRF 拒绝、重复提交与原请求查询。
- 前端 8 项单元测试、类型检查、契约一致性与生产构建通过；生产包排除演示数据。lint 无错误，保留 3 条既有组件 Fast Refresh 提示。
- Chromium 7 项定向用例通过：375px 夜间、1440px 日间授权完整流程，预览冲突重做，以及新增、禁用、重新启用、授权调整四种操作的丢响应恢复。两种宽度均无页面横向溢出；失联撤销显示部分完成。
- Node.js 26.12.1、pnpm 12.18.0 用于前端最终检查。契约首次生成使用系统 pnpm 入口时提示其内部 Node 24/pnpm 11 不匹配，后续切回项目固定入口，类型与生成一致性检查通过。
- 相关文档 lychee 检查 57 处链接、47 个唯一目标全部通过；差异空白检查通过。
