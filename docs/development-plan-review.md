# sbctl 开发文档审查记录

日期：2026 年 11 月 14 日。范围：[产品开发方案](product-development-plan.md) 0.3 至 0.4；审查及修订文档，不实施代码或服务器部署。

结论：保留常驻管理 VPS、Tailscale 加受限 OpenSSH、节点持久记账及静态订阅的总体架构；按用户新确认的方向改为服务器端业务容器部署，保留 React、TypeScript、Vite、Tailwind CSS、shadcn/ui 后台。发现的问题已补入对应规格、任务和验收项；一项影响节点可用性的异常策略留待 M2 前决定。

“已修订”仅表示文档明确了行为与验证要求，不表示实现通过测试。P1 表示可能恢复已撤销权限、造成错误记账或扩大系统权限的问题；P2 表示影响功能落地、操作恢复、兼容性或验收可信度的问题。此处的审查优先级与主方案 FR 功能优先级分别使用。

## 二 尚待明确的异常行为

D01：节点可管理，但撤销用户后的候选配置预检失败，旧 sing-box 容器仍在运行。

| 选择 | 后果 |
| --- | --- |
| 强制停止该节点受管 sing-box 容器 | 阻止被撤销用户继续使用，但该节点所有用户暂时中断，需维护修复后恢复 |
| 保留旧服务并持续重试 | 其他用户继续使用，但被撤销用户在该节点仍可能有效，必须持续显示 revoke_blocked 和高优先级告警 |

建议默认优先撤销，在这一异常情况下停止受影响容器；这只是建议，尚未作为用户已确认策略写入。用户此前接受的是正常配置更新后的重启重连，并未明确选择预检失败后的整节点停服行为。

确定阶段：M2 前；对应 M2.6、AT51。该决策不阻止 F0 或独立的 M0 能力准备。无论选择哪种，不能把失败撤销显示为完成，也不能恢复包含已撤销凭证的旧配置。

## 三 技术依据及验证边界

- 容器模型依据 [Docker host 网络](https://docs.docker.com/engine/network/drivers/host/)、[bind mount](https://docs.docker.com/engine/storage/bind-mounts/) 与 [restart policy](https://docs.docker.com/engine/containers/start-containers-automatically/)；固定 helper 和启动守卫是本产品的设计要求，Docker 不会替产品验证授权状态。
- 内核与统计语义对应固定版本 [sing-box v1.14.4 计数源码](https://github.com/SagerNet/sing-box/blob/v1.14.4/experimental/v2rayapi/stats.go)；同用户双协议、双代凭证及实际字节归属仍由 M0/M3 验证。
- 多连接、只读访问及运行库要求依据 [SQLite WAL 文档](https://www.sqlite.org/wal.html)，断电持久性要求参照 [fsync 文档](https://man7.org/linux/man-pages/man2/fsync.2.html)；这些依据不能替代 Linux 文件系统和故障注入测试。
- 表格选型核对了当前 [shadcn Base UI Data Table 示例](https://ui.shadcn.com/docs/components/base/data-table)。主方案保留此前查询的稳定依赖快照，完整依赖组合尚未安装和运行，F0 必须验证后锁定。

审查采用完整文档阅读、0.3/0.4 差异核对、关键状态场景推演和官方依据核实。此次续接保留上一轮已完成的事实核对，补齐启动屏障提交次序、交叉表述和审查记录；不重复执行已完成的能力调研。

文档验证结果在下节记录。没有安装数据库或项目依赖，没有在本机运行 Docker，没有连接或改变 VPS，也没有执行镜像构建、真实浏览器、真实客户端或流量负载验收。
